# GitHub Issues Guide

This document defines the issue formatting rules for `implementation/ISSUES.md`.

## Issue Format

All issues must follow this template:

### Issue #[Number]: [Title]

**Status:** [Open | In Progress | Closed]
**Scope:** [Frontend | Backend | Documentation | DevOps]
**Description:**
[A brief description of the task.]

**Acceptance Criteria:**

- [ ] Criterion 1
- [ ] Criterion 2

**Dependencies:**
[Any tasks or prerequisites that must be completed first, e.g., Issue #1]

**Related Plan:**
[Path to the relevant Implementation Plan, e.g., implementation/PROJECT_CONTEXT_PLAN.md]

**Completion Notes:**
[Any notes or PR references after the issue is closed.]

## Status Workflow

- **Open:** The issue is ready to be worked on but work has not started.
- **In Progress:** The issue is actively being worked on.
- **Closed:** All acceptance criteria are met, verified, and the code/documentation is committed.
